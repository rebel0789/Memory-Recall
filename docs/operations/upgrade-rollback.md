# Upgrade and Rollback

## Implemented OAF-029 Rehearsal

`packages/operations` creates a local backup manifest with application version,
operations version, component checksums, migration plan state, artifact export
fingerprint, and an external-writes-disabled assertion.

Before an upgrade:

1. Stop the affected local service or quiesce writes.
2. Run `npm run ops:smoke`.
3. Create a backup with external writes disabled.
4. Verify `manifest.json`, `manifest.json.sha256`, component checksums,
   migration status, and artifact object hashes.
5. Restore the backup into an isolated directory and run read-only health checks.
6. Apply the upgrade only after the rehearsal passes.

## Rollback

Rollback uses the same backup manifest. The rollback plan generated by
`createRollbackPlan` requires external writes to remain disabled, verifies the
backup before writing state, restores into an isolated workspace first, and runs
read-only health and representative queries before traffic is switched back.

Do not blindly repeat ambiguous consequential effects after rollback. Use the
durable idempotency records and event history to decide what already committed.

## Production Boundary

OAF-029 does not implement production SSO, hosted secret management, encrypted
backup storage, container image digest pinning, PostgreSQL physical backup,
managed retention workers, or team deployment automation. Those remain release
readiness requirements and must not be inferred from local backup/restore tests.
